# EdenWorX Release Process

## Version Numbering

EdenWorX products follow semantic versioning: **MAJOR.MINOR.PATCH**

- **MAJOR**: Incompatible API changes
- **MINOR**: Backward-compatible additions
- **PATCH**: Backward-compatible bug fixes

Version macros are defined in a `config.h` file, generated by CMake from its corresponding `config.h.in` file.

## Pre-Release Checklist

Before creating a release, verify:

1. **All tests pass**:

   ```bash
   make test
   make test-all
   ```

2. **Sanitizer builds pass**:

   ```bash
   make test-asan
   make test-ubsan
   make test-tsan
   ```

3. **Static analysis clean**:

   ```bash
   clang-tidy -p cmake-build-release src/**/*.cpp
   bash tools/run-cppcheck.sh
   ```

4. **Documentation builds**:

   ```bash
   make doc
   ```

5. **Installation works**:

   ```bash
   make install
   make install PREFIX=/tmp/ewx-test
   ```

6. **No critical issues**: No open General or Important issues remain (all resolved).

7. **No documentation gaps**: All public APIs have Doxygen comments.

   Verify with `make doc` and check for undocumented warnings.

8. **CHANGELOG.md is up to date**: All changes since last release documented.

9. **Version numbers are correct**: Check `CMakeLists.txt` project version
    and the generated `config.h` are consistent.

## Creating a Release

### 1. Update Version

Update the version in `CMakeLists.txt`:

```cmake
project( <project_name>
         VERSION X.Y.Z
         ...
         )
```

The version is the single source of truth in `CMakeLists.txt`; the generated `config.h` is produced from its corresponding
`config.h.in` and must not be edited by hand.

### 2. Update CHANGELOG.md

Add a new section for the release version with all changes since the previous release. Follow the existing format:

```markdown
## X.Y.Z (YYYY-MM-DD)

### Added
- ...

### Changed
- ...

### Fixed
- ...
```

### 3. Build and Verify

```bash
make clean && make && make test && make test-all
make doc
make install
```

### 4. Commit and Tag

```bash
git add -A
git commit -m "Version X.Y.Z Release"
git tag -s vX.Y.Z -m "Version X.Y.Z Release"
```

### 5. Push

```bash
git push 
git push --tags
```

### 6. Create GitHub Release

Use the GitHub web interface:

- Project ->
   - Releases ->
      - Create a new release

## Post-Release

1. Verify the release artifacts are downloadable and installable.
2. Update the project website if applicable.
3. Announce the release on relevant channels.
